# 2026-11-14: E028, the direct search on Maniac Mansion (SCUMM v2)

Question (plan: `experiments/E028-maniac/plan.md`): with the bridge taught what SCUMM v2 does differently, and nothing
taught about the game, how far does E027's search get in Maniac Mansion (DOS enhanced, ScummVM `maniac`, V2/DOS/English)
from the boot, in one chain of runs?

## Before any change: where the unchanged search stops

A smoke run of the unchanged search (high5, 2 threads): `boot: frame 200000 room 45 idle None`, then no trial. Six
readers and a critic read the bridge, the search and the engine for every place they assume v5. What they found, in
the order it is needed:

1. The idle rule reads the input handler's and the sentence script's numbers from `VAR_VERB_SCRIPT` and
   `VAR_SENTENCE_SCRIPT`. v2 sets neither (both are 0xFF, so the rule read an ordinary variable, 0); its engine runs
   global script 4 for input and global script 2 for sentences by fixed number. A free run of 75,000 frames: frame 1
   blocked by the fade, every later frame `no_handler` in room 45 (the kid selection). The segment never started, so no
   skip was ever pressed. Replaying the frame log's verdict with the two numbers changed: idle from frame 3.
2. The sentence line is drawn from the sentence variables, not from a verb slot. A verb click changes the interface's
   hash only through one variable, so one verb per round survived and no verb + object sentence was made.
3. v2's inventory is four boxes and two arrows hit-tested in C++, not verb slots: nothing carried could be used.
4. v2 actors' positions are kept in v2 units (`getPos()` scales them, `getRealPos()` does not), so actor clicks missed.

Also found, not needed for the first run: the input handler's hover loop on verb 15 (it keeps global 4 running), the
input log's hooks (v2's overrides have none), the end site (`o2_restart`, both for an ending and for a game over), a
v2 scripts dump for `--go`, and PROBE_LONG's overshoot when a boot never idles (a separate change, to be measured on MI).

## Patch 0012 (`scumm-speedrun-v2`)

Every change is inside a `version <= 2` branch (v1-v2; v0 handles its own clicks and is left out) or gives the same
value on v3 and later:

- The input and sentence scripts' numbers: 4 and 2 on v2 (the engine's own constants, script.cpp), the variables
  otherwise. On v2 a running global 4 does not block idle by itself (the hover loop); an object script, the sentence
  queue and the sentence script still do.
- The message wait on v1-v2 is the bare opcode 0xAE (v0's 0xAE is another opcode, so v0 is excluded).
- The '.' gate: an unset `VAR_TALKSTOP_KEY` means '.' is on for v2, as in the engine's keyboard handler.
- Slots past the verbs, v1-v2 only: the sentence line (id 256, never clickable), the four inventory boxes (257-260,
  listed while the box holds an object, named by the object's number) and the two arrows (261-262, listed only when a
  click would turn the page). A read-only hit test follows the engine's v2 click order and never calls its inventory
  code.
- Actors' positions through `getPos()` (the same as `getRealPos()` above v2) in every dump, and elevation in the
  same units.

## Smoke: 15 minutes from the boot (high6, 3 threads, the full flag set, no guide, no rungs)

Raw: `/var/tmp/fast-mi/direct/mm-smoke15`; summary, progress and ways in `experiments/E028-maniac/results/smoke15`.

- Boot: frame 2, room 45, idle (prediction: frame < 10). The intro's two scripts are skipped at frames 211 and 213
  and control comes back at frame 231 in room 44 (without skips, frame 1,439).
- Rooms: 45 at 0 s, 44 at 7.6 s, 1 at 23.6 s, 10 at 361 s (the house: through a door opened with an object carried,
  the sentence verb, door, box 257). Stop 194 replays from the boot: frame 765, 17 clicks.
- Level 1 (one object owned) at 192 s. 222,548 trials, 254 stops kept, 47 expanded.
- Prediction "the house entered within 30 minutes": held at 6 minutes.

What it showed as limits:

1. Cost per stop: a stop with the 15 verbs on screen has 160-1,200 half-made sentences; one expansion costs 2,000 to
   20,000 trials (10-80 s at 3 threads). 31 stops past the kid selection were expanded in 15 minutes.
2. Order: the room-10 stop (the first queue) waited from 361 s to the end while 16 room-1 stops of the same line were
   expanded. Read from the code, not measured: `--born-first` puts the results of the line's first stop, in its room,
   before the rest of the line.
3. No scripts dump for v2: `mentions: 0 objects, 0 flags`, so `--go` has nothing to walk to.
4. 36% of stops kept are on the kid selection (waits and portrait orders), though each costs only 26-135 trials.
