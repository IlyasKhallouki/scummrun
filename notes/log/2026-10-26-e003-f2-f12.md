## F12: value sets and ranges

The mouse variables at a click are ranges from the engine's clipping and the camera clamp (input.cpp:414-434,
camera.cpp:169-192). findObject is 0 or one of the room's objects, actorFromPos 0 to 12. A test all values agree on
is decided; a fork narrows a written variable or a local on each side. In the reader, a fact read only by a
comparison forks into the two value sets the comparison separates.

Model check: no certain prediction changes.

| row | precision at done, with F12 | without |
|---|---|---|
| 5, on F2 | 78.9% (855/1084) | 78.9% (855/1084) |
| 4, on F2 | 75.5% (633/838) | 75.5% (633/838) |
| 4, const_polls alone | 75.1% (696/927) | 75.1% (696/927) |

Paths fall from 9,820 to 9,394 (row 5 on F2). The path limit cuts fewer paths in two moves (S1#33: 119 to 70;
S1#36: 45 to 38). Possible predictions change in 44 moves: the hover variables now hold the hovered object's values
(0, the actors and the room's objects) where they held none. Recall with possible gains one fact (S2#30).

Why no certain prediction moves: model.py's merges join paths at every join point, so a narrowed value goes back to
the whole set after the next join. And where the values go on, F12 does not split them: in S1#45 the hover script
uses the mouse band as an index (`Var[133 + band]`, the inventory slot under the cursor) and the hovered object as an
object and a script number, which stay unknown.

is then compared.

## Found in the review

- VAR_VIRT_MOUSE_X can be negative: in a room narrower than the screen the camera is clamped to the width less 160,
  and the screen starts left of 0. The game has two 8-pixel rooms (left edge -312). The range now comes from the
  click's room.
- The main screen's height starts at resetScumm's (128 for v5), not only at the scripts' SetScreen.
- Narrowing could rewrite a reader step counter or a conditional write; it now narrows only the value the test
  decided on, and only the machine's own unknowns.
- A range was listed before its size was checked; it is now counted first (65,536 at most).
- due_engine.py replays run B with the ground truth's engine settings, so with its seed: a replay of run B's
  recorded inputs, as the rules allow, not a system run.
