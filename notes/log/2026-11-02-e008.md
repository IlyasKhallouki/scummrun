# 2026-11-02: E008, exploring from the real game with an archive of engine states

Question: Part I cannot be read ahead of time (E004 stopped in pass 1 after 8,001 CPU s, E005 ran out of memory). Small
readings from a concrete state are cheap. Can the system reach a goal by exploring from the real game instead: keep
an archive of exact engine states grouped into cells by model facts, pick a cell by a fixed order, return to its state
exactly, read only the rooms around it from that state, plan a short step toward a target that a static write map
regressed from the goal ranks, play it with the strict window search, and keep every state the play reaches? Stage 1
asks it of the k = 2 scope's two goals from the boot, without reading the 10 rooms up front.

Plan, interfaces and predictions, written before the code: `experiments/E008-go-explore/plan.md` (Lemma C, the guide,
the order, an amendment with step 0's numbers made before stage 1). Code: `guide.py`, `step.py`, `explore.py` in that
folder, new files only. Numbers: `experiments/E008-go-explore/results/`. Seed 1 only.

Answer: partly. The bar's kitchen door (state:316 = 1) was reached in one job from the boot, on the ring of room 33
that the explorer chose from the files: 401 frames (9,624 qf, 40.10 s), verified from boot with 0 differences. The
kitchen (owner:566 = ego) was not reached: the first job's target led into a dialog in room 38 that the harness cannot
act from, and every later job let the engine idle one frame there. The run was stopped by hand after 15 jobs.

## The guide

The write map regressed from the goal reaches about 1,162 atoms over 805 keys for every goal tried (door, kitchen,
Part I); the goals differ in depth only (at most 4 to 6). Of the 1,487 atoms that any test or start need names, R holds
nearly all. Two things make it saturate. A global script's start needs are the union over every unit that starts it
(global 17 is started from 129 places and has 442 start-need atoms). A looping dispatcher (global 56) puts each of its
tests on the way to each of its writes. Reading "the tests on the way" as control dependence, measured only, gives 961
atoms. The map following computed starts is only 1.02 times larger. The door's
writers include room 28's locals 205 and 209, and room = 28 is at depth 1. For evaluation only, 86 of the 99 Part I key
facts have their key in R.

## Return and Lemma C

An entry is stored as a segment of input events after its parent's frame. A return boots a fresh engine with the
chain's concatenated movie and compares the state at the entry's frame with the stored checkpoint. All 18 returns in
the runs (door 1, kitchen 15, smoke 2) were the same. Four chains were played from boot with no fork and checked at
every checkpoint, each with 0 differences: the door's goal (1 segment, 6 checkpoints), the smoke's goal (2 segments, 16
checkpoints), a smoke entry (1 segment), and the kitchen's deepest chain (8 segments from 8 jobs, 12 checkpoints).
Premise S held throughout: no job sent an input at or before its entry's frame.

## The kitchen

The first job reads the same ring. It reaches no value of room 41, so owner:566 = 1 is no target. The order takes
tier 1 by depth, then key, and the first of 54 targets is bit:108 = 1 (depth 2), ahead of room = 28 (depth 2, 29th).
Its plan walks to room 38 and starts room 38's local 202, which waits in a dialog. Then two refinements: var 103 at
2848, and var 194 at 2862, which the dialog tests at [031A]. The refined reading breaks Lemma R's premise R0, since its
last pass writes values of var 194 outside the domain, and the harness stops there.

Every later job from the dialog goes the same way:

- the ring(38) reading (33, 38, 83, 85, 96) from the dialog state takes 3 to 4 s and gives 9,440 records;
- the first untried target plans in 1 s, and the plan starts with the dialog's escape input;
- the window refutes the dialog's event one frame on (var 194 is not a fact of the reading), and the refinement breaks
  R0 again before any input is sent.

The new entry is one frame later. Two consecutive frames differ only in var 100, a scratch variable that 150 units
write and that changes every frame here. (var:100, any) is in R at depth 1, so each frame makes a new cell holding a
new pair. The order (#g, not favoured, n, −#r, tick, id) then always takes the newest frame first. The second worker
takes the frame before it with its next target, which leads back to a state already in the archive.

Run on with no input, the engine stays idle in that dialog at every frame checked up to 4000. No stop rule can fire
soon. Nothing is exhausted, and stagnation needs a full sweep with no new pair, while each frame brings a new value of
var 100 and a new cell. 14 jobs moved the frontier 7 frames in 4.2 minutes, and the run was stopped by hand.

In the smoke run (rooms 28, 33, 41 allowed, one worker), the first job's ring was (28, 33). Its first target,
bit:118 = 1, ran to the planner's 600 s limit with no plan. Its second, bit:348 = 1, ended in room 28. From there the
next job read (28, 33, 41) and reached the goal from the plan's records at 3216: 488 frames and 11,712 qf from the
boot, E007's time.

## What the measurements call for

- A step can end in an engine state the harness cannot act from. Here, in room 38's dialog, the test on var 194 makes
  the refinement break R0 before any input, so the job only lets the engine idle one frame. The explorer has no
  expansion of its own for such a state (the engine-only expansion was left out of E008).
- A key whose value changes every frame while the engine idles (var 100 here) makes each idle frame a new cell and a
  new pair. This turns an unproductive frontier into an endless one, where neither exhaustion nor stagnation fires,
  and the order prefers it.
- The guide saturates through start needs. It orders the targets of a scope by key name within a depth, and about 600
  atoms sit at depths 2 and 3, so the order inside a depth carries most of the choice.
- A target with no plan costs up to the planner's 600 s limit (the smoke's bit:118 = 1), and a job tries its targets
  in turn until one plans.
