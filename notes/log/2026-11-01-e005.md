# 2026-11-01: E005, narrowing the havoc closures of the rough reading

Question: with (A) a room change in a havoc closure naming only the exit code of the rooms it can leave and the entry
code of the rooms it can load, and (B) a computed script start naming only the scripts its callers can pass, does the
rough reading of Part I finish, and does lama-first find a plan from it to Part I's end? Plan, prediction and stop rule:
`experiments/E005-narrow-havoc/plan.md` (01df853, before any code). Rules and proofs: `havoc-rooms.md`,
`havoc-args.md` (bf14bd5). Numbers: `experiments/E005-narrow-havoc/results/`.

## What was built

- **havoc_args** (args.rs, 1245119): a static analysis of the game's code. Each unit's locals are sets of up to 64
  numbers or ranges, from what its launches pass, its own writes and the conditions on the way; a variable a
  condition narrows holds until the next op. Launches are read from the whole game; a hook's or the boot's script
  has unknown arguments, room code none. The analysis runs to a fixpoint over the computed starts. On Part I's table
  it takes 0.5 s and 9 rounds and leaves no start of the game unknown.
- **havoc_rooms** (havoc.rs, 00a7832): a room change names the exit code of `R0 ∪ T` and the entry code of every `T`,
  where `R0` is the cut path's rooms and `T` the rooms each change can load: its operand's values, or for
  `actorFollowCamera` the actor's room at the cut and the rooms the closure puts it in. A pending startScene step
  holds its room. Local scripts, drawObject's room, `objpos:` and the killed slots follow the same rooms.
- Both are off by default. Off, the kitchen's packed file keeps sha1 279b7a24 (0 differences from golden.py's), and
  the reader's tests pass (101 in 13 suites).

One thing the plan did not name: global 23 sets Local[0] on its inventory branch from `Var[133 + Local[2]]`, with
Local[2] computed from the mouse. Bounding it needed `VAR_MOUSE_X > 160` and `VAR_MOUSE_Y > 152` to narrow those
variables, and the mouse's screen range (F12's). That went into havoc-args.md before any run (51250a2).

- The computed `startObject` in globals 9 and 23. havoc_starts names every object's entry for the verb, so all 202
  objects of the scope, and their code changes the room to constant rooms across the scope. That alone fills the
  closure. A diagnostic build in which such a start names no object (unsound, a measurement only, not committed) gives
  65 units and 1,160 facts at the same cut, not 564 and 2,181.

What the measurements point to: bounding a computed startObject's object from the code (findObject gives an object loaded
in the current room; an inventory script's objects are those the code can give to the ego), and the ego's room as a
fact. Neither is part of E005.
