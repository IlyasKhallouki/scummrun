## How the reader chooses its facts

domains.rs gives a variable a finite domain only when its writes are constants or steps once call arguments are bound.
The sentence script writes var 103 from its local 1, the sentence's first object, which the engine binds, so var 103
has none. FactTable then calls a key a fact when the scope writes it and it has a domain, a constant when the scope does
not write it, a non-fact otherwise. A non-fact reads as an unknown: a test on it becomes a check with both sides read,
and its writes stay out of the task.

## Lemma R and the switch

`--fact-vars N` gives a non-fact var:N a domain in the table's `extra`, seeded with its value in the reading's start
and in each further start, and the reader's own passes widen it with every value a path writes. A path of the refined
reading A2 runs the instructions of a path of A; where A read v as an unknown and followed both sides of a test on it,
A2 forks the read on v's domain and each branch decides the test. So each record of A2 is a record of A with `v ∈ S`
added to its precondition, its checks on v dropped and v's own writes added: given that the domain holds every value v
takes in the engine (R0), A2 still over-approximates the engine and only splits paths A had. Records already played
stay runs of the refined task; the harness keeps the inputs and checkpoints and plans again. The new fact's value at
the replan is the engine's, from the dump; the refinement reads with the engine's state as a further start, so that
value seeds the domain and is reached. Each refinement adds a variable the scope writes and the reading holds no fact
of, so the loop ends; a variable named again stops the run.

## The loop

After a window that ends a plan's play with a replan (a deviation, an empty window, a guessed write), the harness reads
B1's cause. A split whose test read variables of kind "not a fact of the reading" adds them all; any other cause adds
nothing and the harness's rules go on (a deviation replans; a second identical empty window stops). The refiner reads
the scope from the reading's start, the reach extension's starts and the engine's state now, with the reading's own
switches and the run's fact variables, and later rereads keep those variables. Before the reread the harness closes its
planner process.
