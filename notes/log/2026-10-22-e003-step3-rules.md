# 2026-10-22: E003 step 3, scoring rules fixed before the first number

Question: how the model check (E003 plan, step 3) scores the model against run B's Part I, fixed before
any model is scored.

Built so far:
- `groundtruth.py`: the engine's facts before each of run B's 250 Part I moves, at the move's done frame
  and at the next move's start. A second, independent replay agrees on all 750 states.
- `ir.py`: every script as instructions with byte offsets and jump targets. All 7,756 jump targets match
  the raw bytes and descumm's flat output. All 1,400 verb entries are kept.

Rules (fixed now):
- Compare against the state at the move's done frame. The next move's start is reported as a second
  number. The primary stays the done frame whatever the two give.
- Route move to action kind:

  | Route move | Action kind |
  |---|---|
  | verb with one or two objects | sentence |
  | walk to an object | walk-to sentence |
  | choose | dialog line |
  | Esc | skipped cutscene |
  | '.' | wait |
  | walk to a floor point (7 moves) | none, listed separately |

- Denominator: Part I moves minus the 6 glitch moves (README table), the 3 skipped doors and the 2
  composite rows. Where the executor found the move by search (S3#97, S3#98, S3#119), the action is the
  one run B played (`via`), not the route's.
- Precision: micro-averaged over predicted facts. Moves with no prediction are counted and reported.
  With no predictions, precision is undefined, not 100%.
- Recall: over the tracked facts that changed, leaving out variables the engine writes outside script
  opcodes (by their ScummVM index) and facts the model classes as non-facts by its own rule (for
  example, written only from a random draw). No fact is left out by a game number.
- Recall does not gate step 4, but step 5 counts an unpredicted change to a tracked fact as a mismatch.
- The model's code (`model.py`, `actions.py`) imports nothing that reads the route or the ground truth.

Row 0 (the clicked object's own handler, up to its first pause): 239 counted moves, 94.6% accepted,
precision 42.3% at the done frame (39.2% at the next move's start), recall 2.0%. 111 moves predict
nothing, because dialog lines, Esc and waits run nothing at row 0. The largest precision errors are a
hook script recorded as running when it ends in the same frame (73), and the current-object variable
read before the sentence script sets it.

Correction to the recall exclusions: row 0's first run also left out variables the engine writes inside
an opcode (the room change, the message box). Those go back into recall, as the rule above says.

  script waiting on the menu may be one of them. The engine gives those scripts' positions from the
  start of the room or object data, not the script, so the bridge will report a script-relative
  position for every slot.
