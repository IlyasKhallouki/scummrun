## Lemma P and what it asks

o5_wait either returns before any write, and `executeScript` runs the next opcode in the same call, or rewinds and
breaks. So a run whose explain log shows a WaitFor op followed by another opcode is, opcode for opcode, the run of a
path that stops at that op (a record ending there, as the reader ends every record at a WaitFor op it does not resume
at) followed with no step and no frame between by the run of a path that resumes at the op and passes it at its first
test (an event record from that wait point, whose own check says the op does not block). Each part is matched on its
own: the click's record on part 1 by (I1)-(I4), with (I2) the cut and (I4) on part 1's opcodes; the later part as the
own run (Definition S) of the plan's next event of the unit, by M1-M4 on its own opcodes, M2 on the view before the
click's run with the click's record's set writes applied. An event's own run at depth 0 that passed a later wait is cut
the same way.

The second part goes only to the plan's own next record of the unit, armed by the click's record, under 9.2's order
check. A record of the reading the plan does not name would not be a run of the plan's records (Lemma S2), and the
plan's later steps were chosen against the plan's own record's effects. The kitchen's plan 0 already has the event
right after the click in the same macro step, since the door's code is in its path.

Costs: under the split the event runs 0 frames after the click's yield point. costs.rs priced every event at a
WaitForActor, WaitForCamera or WaitForSentence op (433 wait points in the game) and at a WaitForMessage with no talk
before it (258) at 1 frame, as a lower bound, and the chain of Lemma 4 took at least 1 frame on such a link. Neither
allowed 0. With the reader switch those wait points cost 0 (a WaitForMessage after a talk keeps its bound: the talk
sets VAR_HAVE_MSG before the op in the same run), and with `split_wait` the chain adds the cost as it is; the harness
takes `split_wait` only on a reading made with the reader switch.
