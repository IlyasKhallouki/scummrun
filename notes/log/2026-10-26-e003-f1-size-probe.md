# 2026-10-26: E003 fix round 1, F1's size probe

Question: how big does the reading get when an input is one record that starts at the room's input script (F1
with F11), on room 33 and the kitchen (rooms 28 and 41)? fix-round1.md asks for this count before the build. If the
kitchen's taskcore operators or its reading time grow more than 3 times, the build stops and the PI decides.

Answer: the kitchen's reading time grows 4.5 to 6.9 times, its raw operators 5.5 times, and the reading is cut so
much by the reader's path limit that the kitchen task becomes unsolvable. The build stopped here.

## What the probe builds

Branch `fr1-f1-probe` (on `fr1` bb45504), switch `input_script` in scumm-machine and the reader, off by default.

- **Cells (scumm-ir `cells.rs`).** Each room's object list in the engine's order: the OBCD blocks' order in the
  room's ROOM block, read from the resource file (resetRoomObjects, object.cpp:832-901), with each CDHD parent and
  parent state. A cell is a distinct set of boxes over a point, on the 8-pixel grid. The game has 749 cells in 74
  rooms; room 28 has 26, room 41 has 11 and room 33 has 5. In 48 of 83 rooms the list order is not the object order.
- **Machine.** findObject at the mouse's cell is decided by facts: the first object of the cell in list order that is
  not Untouchable, whose parents are in their parent states, and that F5 draws at that place (object.cpp:557-597).
  actorFromPos at a cell is 0, with a replay check. doSentence queues, and the frame's last step runs the queue's
  top (checkAndRunSentenceScript). A held sentence is listed on the record.
- **Reader.** The inputs are a click with each button on each cell of each scope room, and on each shown verb: the
  scope's verbs, its dialog lines (F11) and the slot verbs 200-207 that the input script tests as a range. One record
  is one frame: the mouse moves to the target, the mouse loops (the hover, global 23) take their turns,
  checkExecVerbs reads VAR_USERPUT and VAR_VERB_SCRIPT after them (a dropped click makes no record), the input
  script runs, then the queued sentence. The sentence-building variables are facts: the variables both read and
  written by the input scripts and the mouse loops (kitchen: Var[100], [107]-[110], [118], [181]-[183], [394]). Their
  domains start from the start value and the constants the scope writes, and the passes add what paths write (up to
  six passes). `mouse` is a fact after a click in a room no wider than the screen.
- **Not built:** actor targets, the model check's side, the tests the design lists, the harness.

## Why it grows

1. **Each click runs the whole sentence in its own record.** The input script and the sentence script use the
   sentence variables as numbers: doSentence's verb, A and B, and startObject(A, verb). So a run forks once per
   value. After the first pass, the kitchen's Var[107] holds 21 values and Var[108] holds 12. A click on B while
   Var[110] holds a preposition forks per (verb, A).
2. **The frame's own facts multiply every path.** These include whether the hover is live, unfrozen and at its wait,
   which of the 3 input scripts is installed (Var[32]: 4, 14 or 202), and VAR_USERPUT, the cursor, Bit[547] and
   Bit[563].
3. **When the hover does not run in the frame,** Var[108] and Var[109] keep any value of their domains.
4. **In the bar (640 pixels wide) the mouse is not known after a click.** The hover's later turns then give findObject
   and actorFromPos as value sets. Their objects and actors widen Var[108], Var[109] and Var[181]. The events
   multiply too: there are 1,028 event rounds, and local 208 and local 209 have over 4,000 event records each.
5. **The path limit then cuts most of each input's paths.** The cut paths include the records the goal needs.

What the numbers point to: most of the growth comes from running the queued sentence inside the click's record,
per value of the variables that make it. One alternative keeps the per-click record small: the click's record
ends where the frame queues the sentence, with the queue's verb, A and B copied as facts (no fork). The sentence
script then runs as its own event per sentence, as today's sentence records do.
