# 2026-11-05: E021, the dive needs a quiz answered from a book read two rooms earlier

E021 followed C7's block from E020. Room 42's dive loads room 82 only if `Bit[443]` is set. Room 49's conversation sets
it when two answers match the coordinates (`Var[239]`, `Var[240]`) that reading a held book (object 937, via global
script 98) draws. Details and numbers are in `experiments/E021-quiz/plan.md`.

## What was found, in order

1. **The quiz never counted because the book was never read.** None of play9's 4,176 states holds a drawn coordinate.
   With both at 0, the engine itself could not count an answer.
2. **The book was never read because the bridge failed every run that saved or loaded.**
   - Reading the book makes the game's own temporary save, shows the page in room 83, and loads the save back.
   - The bridge's ban on saves, meant for the player's keys, ended every such try.
   - Patch 0009 performs the game's temporary saves and loads in the engine's memory (`FMI_TEMP_SAVES=1`), so a forked
     branch holds its own copy. Reading the book is then realized in 3 candidates and replays from boot with 0
     differences.
3. **The reader can plan the quiz from inside it.** From a state that waits in its second turn, a model try targets
   `bit:443 = 1` and plans the answers. It fails in the engine only because the coordinates were never drawn.
4. **Two reader gaps remain open.**
   - A verb on a held object never reaches the object's code in a reading.
   - Talking to an actor runs the sentence script, not the game's input script, which is where this game handles the
     talk.

## The run

- Within 7 minutes the run held states with the book read, and 4,344 by the stop.
- None of them re-entered the quiz, and the run stopped at C6.
- The conversation's atoms were already held at the place (room 49 holding the kit) by the states made before the
  book was read. Targets and novelty are per place, so they did not offer the conversation again.

## What it says

- The bridge's assumptions about the game, here "no saves during play", are a source of blocks the reader cannot see.
- Exploration keyed by place misses information gained elsewhere: after a fact that changes what a room's code can do,
  the room's interactions need to count as new.
- That is novelty partitioned by context, as in BFWS's partition functions and Go-Explore's cell design. E022 tests
  it, with the context bounded by the keys a room's guards read that only other code writes and that the game never
  clears.
