## The merge

Branch `kitchen`: origin/main (e926bd2), then stuck, noreload, costs. stuck and noreload merged with no conflict.
costs conflicted in 6 files, 14 hunks: plan_fd.py, replay.py, taskcore's main.rs and README, reader_scope.rs and the
reader's port notes. In each, both sides add a line or a section, and both are kept.

One conflict git did not show. plan_fd passes `args`, the caps file among them, as the server's options, and serve
never read the caps. So a run with serve and caps would have started a server per plan, reloading the file each time,
and planned with the file's costs, with no error.

The fix: `--cost-caps` is a request's option. `sas` applies caps to the loaded task before the bans, so all that serve
keeps depends on them. A request whose caps differ sets the loaded task's costs back to the file's, applies its caps
and builds again from the loaded task. plan_fd sends the caps with the request, so one server stays.
