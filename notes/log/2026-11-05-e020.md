# 2026-11-05: E020, a room reads the code of the objects held in it; play10 reaches C6

E020 tested one cause of play10's stall at C5 (room 42 holding object 946). A room's reading did not read the code of
objects defined in another room that an actor holds. Details and numbers are in `experiments/E020-held-code/plan.md`.

## Result: C6, then a stall on a choice made two rooms earlier

- **What blocked C6:** the kit's (946) Use handler is defined in room 69. It is the code that starts room 42's script
  212, which patches the suit (`class:491:12` cleared). The room-42 reading never read it, so `class:491:12 = 0` was
  never a target.
- **The fix (`FMI_READ_HELD=1`):** held objects from other rooms are read and become sentence objects. The room-42
  targets went from 4 to 12. C6 came one minute into the resume, and its entry replays from boot.
- **What blocks C7:** the dive into room 82 needs `Bit[443]`, which only the room-49 conversation sets, after two right
  answers about where to sail. Room 42 reads it after a trip, a repair, a suit and a hoist. No saved state ever holds it,
  and the room-49 readings do not reach the write.

## What running found, in order

Each problem was found by running and diagnosed from the archive, the reader's reports or the engine's code. Each fix
is general and behind a switch, with a test.

1. **A held-code reading is 420-439k records** (1,507 without the switch): 62-148 s of wall and 330 MB on disk. 138k of
   its 151k actions are events of the interface script 59. The suit's cutscene restarts it through scripts 19 and 59,
   and the reader branches over the mouse state.
2. **The disk filled** when five tries read the same room fresh at once. The fix, `FMI_READ_SHARE=1`: one fresh reading
   of a scope at a time, shared when reusable. The boot disk also grew from 30 to 60 GB.
3. **A return differed on `VAR_SOUNDRESULT`** and stopped the run.
   - The first diagnosis, iMUSE in wall time, was wrong: the bridge already pumps the mixer by game time. Its patch
     (0008) fixed nothing.
   - What is shown: a try's live engine records −1 at the states after the cutscene, and a boot replay of the same
     inputs gives 0. This holds with realize off and with the kept engines off. The cause is open.
   - The fix, `FMI_SKIP_SOUNDRESULT=1`: checkpoints are compared without it. Every script sets it and reads it at the
     next instruction, so no script reads it across a frame. Every other fact is still compared.
   - `FMI_DIFFERS_DEAD=1` marks an entry whose return differs as dead, and the run goes on.
4. **In-process readings stopped at 8 GB of RSS.** The RSS measured is the driver's, which held 12 GB at 20 workers, so
   every reading counted the other tries' growth. `FMI_READ_MAX_RSS_GB` makes the bound settable.

## What the stall at C7 says

The stall comes from a property of the game, not a missing interface. A choice's effect is checked two rooms and many
steps later, and it is invisible until then. Novelty over atoms cannot value it (the bit is never set), and room 49's
reading does not reach it. Two things are missing:

- a reading that follows a conversation's answer counter across its turns;
- regression across places, so that a condition a stuck place checks becomes a target where some code writes it.
