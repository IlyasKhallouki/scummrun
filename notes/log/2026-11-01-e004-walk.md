## The reader switch

- **What the reader did.** It ended a record at every WaitFor op it did not resume at (machine.rs `Reader::wait`);
  only the wait an event resumes at fell through. None of the four subops' tests is a fact of the reading: an actor's
  moving state, VAR_HAVE_MSG (an engine variable written every frame), the camera's position and target; WaitForSentence
  reads the sentence queue, which no fact holds, and whether the sentence script is in use, which one does.
- **The rule.** With `wait_both`, such a wait also passes in the same run, the record carrying "`<op>` blocks" on the
  side false; WaitForSentence keeps the exact branch where the path decides it (the sentence script in use: it blocks;
  not in use with a sentence the path queued on top: its freeze count decides). Lemma W: o5_wait either returns having
  written nothing or rewinds and breaks, so the passing branch starts from the state the blocking one stops in, and the
  switch only adds paths (drops one only where the path decides WaitForSentence).
- **Off.** `reader-port read kitchen --packed`: sha1 279b7a24, 72,258 lines compared with golden.py's, 0 differences.
  The reader's and machine's tests pass (97; the slow ignored ones not run), with two new ones on room 33 read in one
  pass: off, no record passes a wait it does not resume at; on, every record of the reading off is still there and
  records that pass the sentence script's waits are added.
- **On.** On the kitchen reading, walk_to(428) has 130 actions (18 off); 110 pass [02E0] in the same run. The
  scopes measured here hold no WaitForSentence (the game has two, in one room outside them), so its exact branch is
  not exercised by these readings.

## The strict search's faults (window-search.md 9.8)

- **(I4) on the engine's own opcodes.** A click's checks were decided on the dump at the fork. Now the children arm
  `explain` for the units the click's records' checks cite, and a check is read from the click's own run of its unit:
  the opcode after a conditional jump (o5 jumps when the condition is false), or whether the run ended at a WaitFor op.
  An event's check is read the same way from its own run when the branch's log holds it. Where no run of the check's
  unit is logged, the dump decides, as before.
- **Effects outside their domain** are reported per window, for the parent and the chosen child, with the record, the
  fact, the engine's value and the domain; under trace-validation.md section 3 the record still matches.
- **Labels.** A window that ends in a deviation logs its input as "deviation" (it said "window empty").
- **The classes.** A variable or bit is a fact only if the reading's domains hold it (B1 took every variable some
  script writes knownly as a fact); a write of a constant takes the class of the test that sent the run to it (it was
  always semantics). The k = 2 door sentence's cause: the sentence script reaches its constant write of var 102 at
  [002B] only through the tests at [0000] and [0007] on vars 103 and 104, which the kitchen's reading holds no fact of:
  split by the section's own rule.

## What the measurements call for

The engine's run that passed [02E0] is, step by step, the click's record up to the wait followed by the event record
the reading already has at that wait (`event(script:2@736)`), with no other run between them: o5_wait writes nothing.
The reading without the switch therefore holds every piece of it; what it lacks is (1) a match that lets the event's own
run be the rest of the click's run from the wait (Definition S counts an executeScript call as one run), and (2) a frame
cost of 0 for an event at a WaitFor op that can pass at once (the rule gives 1 frame, which a pass in the same run
breaks: A2). Matching the passed wait as two segments of one run leaves the reading's records and the planner's task
about as they are (44,605 operators; only the costs of those events change), where materializing every pass in the
reader multiplies the task by 38. Either way the strict
rule stays one record, one stretch of the engine's opcodes, each with M1 to M4.
