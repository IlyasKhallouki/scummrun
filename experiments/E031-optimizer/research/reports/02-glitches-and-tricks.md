# Glitches and tricks under Any% rules, and which the system could find

A research report made for E031's plan (2026-11-16) by a reading agent; its claims were used in the plan after the plan's critics checked them. Evidence paths are as the agent gave them.

## Findings

### 1. Measure everything against a corrected baseline. full5's reported end comes about 10 minutes after the end flag first holds. Cutting the movie at the first frame bit 565 holds is a free saving that needs no glitch and no game knowledge, and it can be verified.

- **Evidence:** global/script-132.txt [0142] sets Bit[565]. At [015D] the script starts global 137, whose [004B] loadRoom(85) shows in the from-boot replay trace (/var/tmp/fast-mi/direct/video-full5/verify-out/eng/b0/trace.jsonl) at frame 108,830, tick 657,813. The movie's last click is at frame 108,579. From frame 109,024 the game sits in room 89: global 138, a cutscene with menus and no beginOverride, with CD track 16 looping. The trace has 10 stall records there (blocker 'cutscene', 3,600 to 36,000 ticks not idle). The trial ended on its own bound at frame 114,978. Other facts from the same trace: segment start at frame 2,728, tick 16,321, var 19 = 6; var 19 is 6 at 628 of 629 room changes (12 once, at frame 77,797, during global 44's dam blast); 1,843 text skips and 211 cutscene skips; no scheduled key.
- **Why it matters:** Bit 565 holds by frame 108,830, tick 657,813 (3:02:44) at the latest. That is at least 6,148 frames and 36,888 ticks (10:15) before the reported 114,978 / 694,701. The bound comes from the script order, not from a per-frame check. Every glitch saving below should be read against at most 657,813 ticks. Any%'s own end, the fade after the final cutscene, comes later than bit 565: it needs the two fireworks menu choices and the last lines (routes/anypercent/S7, var 194 == 122 then room 0). So the shortener has to say which end it optimises.

### 2. Logo speed glitch (var 19 left at 5). This is the largest lever that lasts the whole run. The bridge can already produce it with one scheduled Esc. A general boot scan can find it without game-specific knowledge. Once it is in, every later input has to be found again.

- **Evidence:** In engine terms, go() waits VAR_TIMER_NEXT (var 19) jiffies per frame. On DOS CD the boot sets var 19 to 6 (global/script-001.txt [06EB]). Room 10's local 204 sets 5 at [0000] and 6 at [0097]. An Esc while 204 runs takes global 152's override ([004F] goto 089D) and ends 152. The boot then changes room, and the room change kills the room-local 204 before its restore (study guide 03-bridge-rest.md). The other CD writers save what they find and restore it: global 44 (12), global 100 (10), room 51 local 208 (1). So 5 persists. The input is one Esc on a boot frame from 46 to 92 (DOS CD under the bridge, measured in docs/anypercent/findings.md). Auto skips switched on from frame 1 press at the override's first live frame, before 204 starts: E024's MI check (commit 054378d) reached first control at frame 110, tick 660, with var 19 = 6.
- **Why it matters:** Saving: frame-paced motion runs 6/5 as fast (walk steps, animation, breakHere loops). delay(), talk timers and CD waits keep their length (docs/comparison.md §1.4). The forest's 9 hops measured 35.4 s at var 19 = 6, would take 29.5 s at 5, and took 29.3 s in the human IL. The 2017 estimate was about 4 minutes per run (F-SPEED). The upper bound on full5 is 1/6 of the 641,492 ticks from segment start to the end flag, about 106,900 ticks; the real gain is smaller by every fixed wait. Bridge: already works. Raw inputs apply before the segment start (E029 used an Esc at frame 3), so it takes a raw {"key":"esc"} at a frame from 46 to 92 with SPEEDRUN_TIMER_NEXT=any. That is the search host's default; E024's shortener sets the measured value instead, which would forbid the glitch. State: one engine variable changes; no game flag does. Tick-based waits then take more frames, so every later frame-indexed click and random draw shifts, and the whole route must be found again. Decide it first. Discovery: general, engine-level, no game knowledge. Option 1: scan the frame of the first Esc over the boot (about 100 forks) and judge by first-control time plus the bridge's v19, or by a fixed probe walk. Option 2: statically, from an index of VAR_TIMER_NEXT writes, find set/restore pairs in room-local scripts that a room change can kill. Room 10 local 204 qualifies. Room 51 local 208 is shielded by the hard UserputOff at room-051-circus-te/local-207.txt [03B0], before [03CE] starts 208.

### 3. Skipping the intro with patch 0013 (speedrun_skip_early) removes about 15,700 ticks from full5's from-boot clock without touching the search. Used alone, though, it presses Esc too early for the logo glitch.

- **Evidence:** full5 pressed no key before the segment start (the segment-start rule), so the whole intro ran. First control came at frame 2,728, tick 16,321. That includes the Part One card (room 96, 7,800 ticks spent waiting on its CD track) and four 'userput' stall records. With auto skips active from frame 1 (E024 commit 054378d), first control came at frame 110, tick 660. Patch 0013 lets the auto skips press before the segment start, still only on frames where a press has an effect. It acts only through its setting, so the gate's digests do not change (notes/log/2026-11-15-e029-mi2demo.md).
- **Why it matters:** It saves about 15,661 ticks (4:21) on the system's from-boot clock. The Any% clock starts at the logo-skip Esc, so only the stretch after that Esc is timed there. Bridge: already works, via FMI_GAME_INI=speedrun_skip_early=true in the shortener's own engines; the search code is untouched. Timing only for this stretch. To get the glitch as well, put the skips-on event, or a raw Esc, on a frame from 46 to 92 instead of frame 1; 0013 then skips the rest of the intro. Discovery: general (an engine setting plus the bridge's own test of whether a press has an effect).

### 4. Text ('.') and cutscene (Esc) skips are already automatic after the segment start. But skipping on the first effective frame is not always fastest, and it is not always neutral for game state. Choosing per skip is a general search the shortener can run.

- **Evidence:** '.' (VAR_TALKSTOP_KEY = 46) sets _talkDelay = 0 (input.cpp:1418-1419). Esc (VAR_CUTSCENEEXIT_KEY = 27) calls abortCutscene(), which jumps the overriding script to its stored position (script.cpp:1736-1773). The bridge presses through _keyPressed, Esc before '.', on the first effective frame, with a stale-pointer guard (trackOverride). Value of skips on floppy: 470 ticks from the logo Esc to dock control with skips, 3,170 without (findings.md). Esc can change state. The cannibal talk changes unless Esc is pressed right after one particular choice (runner-sources §2.7). An Esc on a reading ends it on its first frame, so no item slide can form (S3 glitch entry). Switching skips on early broke later fixed clicks on the FoA demo (E024). Fewer frames also means fewer per-frame draws (menu waits draw once per frame).
- **Why it matters:** Bridge: already supports skips on/off events at any frame, a 'spare' list of scripts whose lines and override are left alone (used for global 148, the book), and raw '.' and Esc keys. Discovery: general. For each skip in a route, try 'no skip' and 'k frames later', judged by the next step's completion or by the end verified from boot; a reading held open or a different override path shows up as a state difference. A text skip still costs at least one frame per line, so full5's 1,843 skipped lines can only shrink through a route that triggers fewer lines.

### 5. Item slide: a _userPut counter left one level high. It is what the whole DOS CD sequence-break chain rests on. The bridge has produced it (in the hand-routed A runs); the direct search cannot, by construction. Finding it without game knowledge would need machinery that does not exist yet, so in practice it is game-specific knowledge.

- **Evidence:** _userPut is a counter: hard UserputOn/Off set it to 1 or 0, soft On/Off add or subtract 1 (script_v5.cpp:858-887), and input is accepted while it is above 0 (verbs.cpp:590). The cutscene start script 18 does a soft off and freezes scripts that are not freeze-resistant, the hover script 23 included. The end script 19 does a soft on. If a hard On runs while a soft cutscene is open, the counter is one level high after that cutscene ends: 2 at rest and 1 inside any cutscene, so the player keeps control during cutscenes. Room objects are dead then (hover is frozen), but the inventory, verbs and floor clicks still work. The CD setup, from the record and S3: in the crew-phase store, floor-click toward (300,141); Look at the compass while ego is still left of x = 250 (this reading is a cutscene([2])); store local 214, which is freeze-resistant, catches ego at x > 250, walks him back to (232,135) and does a hard On; then Esc the reading. Success test: var 53 == 1 with var 352 == 1. Otis's global 70 cutscene carries the slide through the end of Part I. Any dialogue's hard On (global 32 [0011]) removes it, and the dusty book re-creates it at the cannibals (routes/anypercent S3, S4 and S5 glitch entries).
- **Why it matters:** Saving: none by itself, it only enables the skips built on it. In the record, the CD crew phase is 22.5 s slower than the same runner's EGA crew phase because of the setup; Part III up to the catacombs is 86 s faster and the ghost ship 5.5 s faster, about 69 s net (runner-sources §4.2, an inference). Bridge: proven end to end and verified from boot (runs/anypercent/m2: 23:11.3 RTA, 21:01.5 without CD track 6). Those inputs came from a hand route with search fallback, which the constraints rule out as input. The direct search cannot form a slide: it schedules no keys, and its auto Esc ends every reading on its first frame. State: engine control state changes, and every break built on it changes game state. Discovery: no current mechanism finds it. A general one would need three parts: (1) from the scripts, index the absolute userput writes and the triggers that run them (room entry, ego position); (2) try player-started cutscenes (verbs on owned items whose handler opens a cutscene with an override) at varied frames while walking into those triggers, with skips off for that reading; (3) keep any state where the bridge's 'up' is higher than 'cs' implies, as novelty. The payoff comes hours of route later, in Part III, so a step-local judge rejects the setup. Crash risks are engine errors ('Script %d stopped with active cutscene/override'), and a search sees those as ends.

### 6. Oars skip: a sequence break that changes game state (the boat without the oars). It needs the slide plus a click on a map exit while ego is off-room, and it is very specific in both frame and pixel. Game-specific knowledge in practice.

- **Evidence:** During the dam blast, global 44 moves ego to room 0 for 16 slow frames (var 19 = 12) and then puts him back with putActor(148,151). With the slide, any map hotspot click moves an off-room ego (exit 47 to room 5). An exit-62 walk in progress is cut short by the re-placement. Exit 62 then shifts ego by +200 to (348,151), which snaps into room 4's sea box 22, so room 4's entry gives him the boat costume. Inputs: Use lens with sun at the dam; when room 4 shows and ego is gone, click exit 47; in room 5, click a far pixel of exit 62; on the room-4 landing, click 56 at ego's own pixel (316,151); click beach 60; wait for var 19 == 5 before walking (S5 glitch entry). full5's trace shows the dam blast (var 19 = 12 at frame 77,797), done without a slide.
- **Why it matters:** Saving: the pond rope, the crack and the oars. No source gives a figure for this skip alone. In the record it spans fork 15:07 to the beach with the boat at 15:25, and it is part of the 86 s Part III gain. Bridge: proven (A runs). Discovery: general only in principle: inside a slide state, try map-hotspot pixels frame by frame during an unskippable cutscene, with new rooms as novelty. The 16-frame window, the pixel choice and the sea-box snap make blind search very costly. Guard needed: global 44 restores its saved var 19 at [011C]. A route that stopped global 44 between [00E2] and [011C] would leave var 19 at 12 for the rest of the run. The shortener should reject any route whose final var 19 is higher than its value at the start.

### 7. Monkey skip: a reading used as a freeze holds the monkey-head gate open, so the idol is taken without feeding the monkey (a game-state break). The freeze lever itself is general; this instance also needs the slide and a camera-dependent setup.

- **Evidence:** Inputs (S5 glitch entry): Pull the nose; Look at the note on the frame after state(142) becomes 1; floor-click a pixel under the ear on class-138 object 155; Esc; click the same pixel. Mechanism: the reading freezes local 202 inside its wait-for-ego-to-move loop. Local 204, which is freeze-resistant, waits on 202, so the gate stays open. A click on a class-138 object walks to the clicked pixel with no distance check, so the room changes without ego moving and the gate never closes. Precondition: local 202 has panned the camera (var 2 == 624); otherwise Herman's script 209 fires when the reading ends. The same freeze, where frozen scripts' delays do not count down (script.cpp:928-930), gives the fort's reading shield and the runners' Herman skip at the rock.
- **Why it matters:** Saving: about 1:10 on floppy (G-MONKEY-FL); on CD it is part of the 86 s. Bridge: proven (A runs). Discovery: the freeze lever is general (any verb on an owned item whose handler opens a freezing cutscene, judged by the outcome of a race against a script timer). This instance also needs the slide, so ego can walk while reading, and the right camera state.

### 8. Feather (ghost-rat) skip: with the slide, one click inside the rat cutscene runs the sentence that the frozen hover script still holds. A game-state break that needs the slide; the timing is moderately strict.

- **Evidence:** The rat cutscene freezes hover script 23 while it holds Pick up + grease (Var[107] = 9, Var[108] = 806). With the slide, a click inside the cutscene issues that sentence. Its fresh, unfrozen script 2 walks ego back, and the pick-up runs before the rat script's next x check. Inputs: Walk to the grease; press 'p' at least 2 frames before ego's x passes 150, with the cursor on the grease; one left click during the rat's line; a floor click at the ladder's walk point (63,117) after the pick-up, timed so ego is left of x = 150 when the cutscene ends (S6 glitch entry).
- **Why it matters:** Saving: the feather, the two tickles (10 + 20 frames), the grog pick-up, a room round trip and the rats' drinking. Runners estimate 10-15 s (G-COOK-CD). The record is 5.5 s faster than EGA on the ghost ship, and the book that carries the slide costs about 1.4 s (YT-SLIDE). Bridge: proven (A runs). Discovery: in a slide state, frame-by-frame trials of a click inside an unskippable cutscene, judged by owning the item earlier, would find it. Without the slide it is impossible.

### 9. Credit Early was found by the direct search itself on seed 1, with no knowledge of the code. The shortener's job is to keep it and trim it.

- **Evidence:** full5 leg00 node 5469 (frame 20,735, room 30): news bit 320 and owner 397, after 11 handle sentences ('how' v7t390 four times, v5, v6, v7 twice, v5, v7 twice) since the store entry at frame 19,743, 992 frames in all. The trials end later: idol trial at frame 24,083, treasure at 56,215. Mechanism: the store's first entry (frame 3,089 in full5) draws the four-digit combination, Var[221..224], each 1 + getRandomNr(3). Every entry draws whether the storekeeper is present (away 1 time in 4). With him away, the handle feeds local 202's counter, which opens the safe and hands over note 397 (S1 glitch entry; routes/anypercent/README.md RNG point 7).
- **Why it matters:** Saving: the crew phase's second store visit, about 58 s (the same runner's EGA runs with and without Credit Early; runner-sources §3.2). Bridge: works with sentences only; a frame-deterministic bot needs no save/load. State: game state (bit 320, note 397), gated by random draws. For the shortener: (1) ddmin over the 11 handle sentences, judged by bit 320 at the step's end, can bring the sequence down to the combination's digit sum (4 to 16 sentences); (2) the combination and the storekeeper's presence are draw-dependent, so any earlier frame change re-rolls them. E024's twin forks have to mark this step, and finding it again has to solve it again, or restore a good draw with delays. Both are general; no game knowledge is needed.

### 10. Random draws (catacombs, insult fights, Carla, the storekeeper, the church door) can be steered by input timing alone. The bridge is frame-exact and deterministic. A general delay scan with draw detection finds these gains without game knowledge.

- **Evidence:** The RNG is one uint32 xorshift (common/random.cpp). It advances only through script getRandomNr and a few engine effects (a dissolve makes w·h−1 draws). It is not saved in savegames, so a hotkey load is a reroll. 2026.3.0 makes no per-frame engine draw (runner-sources §7). Menu waits draw getRandomNr(1) every frame, so delaying a choice by d frames shifts every later draw (S2 glitch entry). Each catacomb chamber draws its layout on entry, so the frame of the previous exit decides it (findings.md). Under the bridge, CD music and speech timers advance in game time and replays are byte-identical (findings.md), so the CD inconsistencies runners report do not occur here. full5 spent 13,200 ticks (220 s) over 21 visits in room 39, including a second pass (stops 6095 to 6715 on the winning line).
- **Why it matters:** Savings: catacomb exits went from 59 s to 12 s with 0-12 frames of delay per exit and one chamber of look-ahead (findings.md), 47 s on the A run (overnight.md). Look-ahead on the fights and Carla saved 5.4 s (24:14.0 to 24:08.6, overnight.md). The record lost about 10 s to one Carla insult (runner-sources §1.1). Bridge: works (a delay is just a later frame). State: random outcomes change, through legal timing. Discovery: general. E024's twin forks with a perturbed RNG mark the steps that depend on draws (label.rs; on the FoA demo they found the cave and the quiz). Then scan delays 0..D before each marked step with one step of look-ahead, and keep the earliest completion verified from boot. Any% allows choosing the seed (rules/anypercent.md), but each seed means finding the whole route again. Save/load rerolls cannot be delivered: raw key names are esc, space, enter and printable characters, with no Ctrl or Alt (speedrun_inputs.cpp:43-56). They are not needed either.

### 11. Walking and pathing tricks are pure engine arithmetic and fully general. None of full5's clicks uses them. E025 already designed the mechanism (geometry from the live walk boxes proposes, the engine judges); it was never built.

- **Evidence:** From actor.cpp (the v4-6 code path, which v5 shares): (a) Truncated clamp: calcMovementFactor compares trunc(|dX|/65536) with speedx, so a diagonal just under the slope (speedx+1):speedy moves almost speedx+1 px a frame in x. That is +12% for Guybrush at (8,2), +50% on the Mêlée map (2,2) and +100% on the Monkey Island map (1,1). These are mirror results (engine-mechanics §2.4), not engine runs. (b) Fraction reset: every new target zeroes xfrac and yfrac, and the first step floors. Re-clicking every frame therefore gains when moving left or up and loses when moving right or down; moving up at scale 50 goes from 0.39 to 1.00 px a frame (§2.5). (c) Doors: approach so the last leg's facing already matches the door's actordir, which saves 2-3 turn frames (§2.7). (d) Class-138 exits and map hotspots walk to the clicked pixel with no distance check, so click the nearest pixel. A hotspot pixel that snaps into an unreachable box fires the exit at once (the beach warp). Clicking a Monkey Island map hotspot runs script 117 at WalkSpeed(4,4) instead of 118 at (1,1) (S5).
- **Why it matters:** Measured savings: shmoovement on two Part IV walks, 7 + 2 frames (S7, A run). On the FoA demo: a zig-zag cut a walk from 19 to 16 frames and a gate corner from 36 to 28; re-click rules saved 408 ticks route-wide with the 'dir' rule and 492 with a width-6 beam, out of 13,606 (E025 plan). Clicking the Hook Isle cable on the right frame: 0.4 s (V-2445). full5 spent 531 s on the Mêlée map (room 85, 60 visits) and 168-209 s in each of Monkey Island map rooms 4 and 5, where the diagonal effect is largest. Bridge: works (raw clicks every frame). State: timing only, but positions change box triggers, the camera and later draws (before the last draw an earlier arrival is a lottery, E025 H3). Discovery: general; E025 uses no game numbers and judges by arrival, the step, the next step and the end verified from boot.

### 12. Input buffering is not in the task list, but I measured it in full5. The search leaves 2 or 8 frames between a verb click and its object click. Pre-selecting the verb during the previous walk, or pressing the verb key the frame before, could remove most of those frames.

- **Evidence:** full5 movie (end-stop.jsonl): 418 verb/inventory click to scene click pairs. 183 of them are 3 frames apart and 138 are 9 frames apart; the sum of (gap − 1) over pairs up to 30 frames apart is 1,801 frames. The engine takes one click per frame, and Var[107] (the selected verb) persists until changed. engine-mechanics §6.2: verb plus object costs 2 frames, or 1 if the verb is pressed the frame before. LeoLitz's MI2 Lite TAS saved 12 frames at one spot by buffering (runner-sources §6). A right click gives the default verb in one click; the bridge supports rclick, and full5 uses none.
- **Why it matters:** Upper bound about 1,800 frames (about 10,800 ticks, 3 min) on full5. I have not checked what the game needs between the two clicks (hover update, the sentence line), and the gap may come from the search's stop policy rather than from the game. Discovery: a cheap, general scan per pair (place the object click k frames earlier, judged by the sentence starting). Timing only.

### 13. Text speed is a recorded setting (talkspeed, which sets VAR_CHARINC). With automatic '.', it barely matters. It does matter where a reading has to last long enough to hold the slide, so it must be chosen together with the slide decision, before any route is found again.

- **Evidence:** full5 had var 37 = 0 at the segment start (fastest text). '.' ends a line by zeroing _talkDelay whatever the speed; runners agree text speed does not matter with '.' (F-RULES). The slide chain needs long readings: the store reading must outlast local 214's UserputOn (each part lasts 60 + chars × VAR_CHARINC jiffies), and the book must stay open across the cannibal and navigator dialogues. LeoLitz calls slow text close to required (YT-SLIDE), and the A runs used talkspeed 85 for that stretch. In-run '+' and '-' change VAR_CHARINC through a modal banner that waits on the wall clock (input.cpp:1139-1173, showBannerAndPause), so for a bot the speed belongs in the config.
- **Why it matters:** Saving: little by itself, but it enables the slide, and it changes the frame count of every unskipped line, which shifts later draws. Bridge: works (a ScummVM setting through FMI_GAME_INI, recorded as the Any% rules require). Discovery: general (sweep a handful of values, judged by the verified end). It must be fixed before the route is found again.

### 14. Smaller position and timing-window tricks: the forest map teleport, the head skip, the necklace skip and the church door left open. Most are general frame or pixel scans. The forest teleport needs the shortener to try an inventory action in place of a walk. full5 uses none of them.

- **Evidence:** Forest teleport: reading the map in room 207 after entering from 212 re-enters 207 with its walk boxes unlocked, and the costume restore at the end of global 123 snaps ego into the nearest open box, next to path 685 (S1 glitch entry). full5 walked all 9 forest hops (rooms 218 to 201, frames 55,618 to 56,044). Necklace skip: global 141 plays its 20-frame animation only if actor 12, placed at (ego.x, ego.y+1), is in ego's walk box; standing on a line box (room 70 box 8, room 77 box 5) skips it, and the route does this twice (S6). Head skip: globals 110 and 111 return at once when ego is in box 8, 9 or 12; press T and click the head in the 2 frames after the room loads (G-HEAD, S6). Church door 438: a street pirate opens it for 4 frames, and leaving High Street inside that window keeps it open into Part IV (S7).
- **Why it matters:** Savings: the forest teleport replaces about 54 walk frames with about 26 frames of map animation (a reviewer's estimate, not measured); the necklace skip saves 40 frames in all; the head skips about 4 s together (YT-CATA101); the church door about 0.5 s. Discovery: the necklace, head and door tricks are general (scan use points and first-input frames, judged by when the sentence ends; the door by a later state). The forest teleport is general only if the shortener tries inventory actions as replacements for walk stretches and counts 'ego moved without walking' as progress; otherwise it takes game-specific knowledge.

### 15. Not usable on DOS CD under these rules: snap scroll (Ctrl+R, v4 only), the EGA Hook Isle map teleport, Ctrl+W, save/load rerolls through the bridge, the invisible stairs, and No Music. The largest fixed waits left are CD-track waits, which no glitch removes.

- **Evidence:** input.cpp: snapScrollKeyEnabled only for versions 2-4. The EGA teleport is EGA only and is blocked unless kEnhMinorBugFixes is off (runner-sources §4.3). Ctrl+W, debug keys and No Music are banned (rules/anypercent.md, Banned 1-2). Raw key names have no modifiers (speedrun_inputs.cpp:43-56). The invisible stairs only help when the safe is opened on time, which Credit Early makes irrelevant (runner-sources §3.3). full5's trace: the Last Part card (room 95) waited 7,800 ticks for CD track 6, against 0.2 s when the track is missing (overnight.md).
- **Why it matters:** These leave the candidate list. The CD track 6 wait (about 130 s) is a rules question, not a shortening, and it is the largest single fixed item on the route (routes/anypercent/README.md open problem 5).

### 16. Order of work. Settle the levers that span the whole run first (logo Esc frame, intro skip, text speed, slide or no slide), because each one shifts every later frame. Then find the route again. Then apply local tricks (walks, buffering, delays, drops).

- **Evidence:** With var 19 at 5, tick-based delays take more frames; the intro skip removes 2,600 frames or more; text speed changes how many frames each line lasts. Each of these moves every later click and every per-frame draw (menu waits, ambient loops, the map script 24). E024's pass already finds steps again from boot (FoA demo: 34 steps in 79 s), but its reduction rounds grow with the square of the step count, about 3.3 h per round projected for MI Part I (E024 G6). full5's winning line has 1,038 kept stops (traced from leg00-03 nodes.jsonl).
- **Why it matters:** Glitch payoffs are often far downstream: the slide pays off only in Part III. A step-local judge such as E024's earliest-completion scan will reject the setup steps, so slide-type changes need a judge at the later step or at the end verified from boot. Glitches that work through random draws (Credit Early, catacombs) have to be found again after any upstream change.
